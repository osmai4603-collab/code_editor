# تحليل شريط الحالة في VS Code

## 1. نطاق التحليل ومصدره

يحلل هذا المستند شريط الحالة الخاص بـ **Workbench** في نسخة المصدر الموجودة محلياً في:

`/home/osm/Downloads/vscode-main/vscode-main`

المقصود هو الشريط الأفقي في أسفل نافذة VS Code، وليس شريط حالة منفصلاً داخل مساحة نص المحرر. التحليل مبني على قراءة ملفات التنفيذ والأنماط وواجهة الإضافات والاختبارات؛ أسماء الملفات أدناه نسبية إلى جذر نسخة VS Code المذكورة. وقد تتغير التفاصيل مع تحديث المصدر.

## 2. الخلاصة المعمارية

شريط الحالة ليس عنصراً ثابتاً يحوي نصوصاً مكتوبة يدوياً، بل منطقة من مناطق Workbench تُملأ بعناصر مستقلة من مساهمات المحرر والخدمات والإضافات.

```text
Workbench
└── Parts.STATUSBAR_PART (منطقة سفلى، role=status)
    └── StatusbarPart
        ├── StatusbarViewModel     ترتيب العناصر، الإخفاء، التركيز
        ├── left-items             عناصر المحاذاة اليسرى
        └── right-items            عناصر المحاذاة اليمنى
            └── StatusbarEntryItem عرض النص/الأيقونة والتلميح والتفاعل

IStatusbarService
├── MainStatusbarPart             نافذة Workbench الرئيسية
├── AuxiliaryStatusbarPart(s)     نوافذ Workbench المساعدة
└── ScopedStatusbarService        واجهة محصورة بحاوية عناصر محددة
```

المكوّنات الأساسية:

| الطبقة | المسؤولية |
| --- | --- |
| `IStatusbarService` | واجهة الخدمة التي تستخدمها المساهمات لإضافة العناصر وتحديثها وإزالتها. |
| `StatusbarService` | يوفّر الجزء الرئيسي، يدير الأجزاء في النوافذ، ويمرر العمليات إلى الحاوية المناسبة. |
| `StatusbarPart` | يبني DOM، يربط النموذج بالعناصر المرئية، يطبق السمات والأنماط، ويوفر القوائم والتركيز. |
| `StatusbarViewModel` | يحتفظ بالعناصر، يحسب ترتيبها، ويستعيد العناصر المخفية من التخزين. |
| `StatusbarEntryItem` | يعرض العنصر ويتعامل مع الأيقونات والأوامر والـ hover والألوان وإمكانية الوصول. |
| `statusbarpart.css` | يحدد الحجم والتخطيط والـ hover والحالات اللونية والمسافات. |

## 3. المكان في تخطيط المحرر والهيكل المرئي

يسجل `workbench.ts` الجزء بمعرّف `Parts.STATUSBAR_PART` وصنف CSS `statusbar` ودور إمكانية الوصول `status`. ويعرّف `StatusbarService` عناصر الحاوية كـ `footer.part.statusbar`، مع `aria-live="off"` وكون الحاوية قابلة للتركيز. بذلك يكون الشريط منطقة دلالية للحالة، لكن تحديث عناصره لا يُعلن تلقائياً كمنطقة حية لقارئات الشاشة.

الحاوية الداخلية موزعة إلى منطقتين:

```text
+-----------------------------------------------------------------------+
| left-items: عناصر متتابعة من اليسار | right-items: عناصر من اليمين ←  |
+-----------------------------------------------------------------------+
```

- منطقة اليسار تتمدد (`flex-grow: 1`) لدفع منطقة اليمين إلى أقصى الطرف.
- منطقة اليمين تستخدم `row-reverse` وتسمح بالالتفاف؛ عند ضيق المساحة تبدأ العناصر الأقرب إلى اليسار بالالتفاف، للمحافظة على العناصر ذات الأولوية عند الطرف الأيمن.
- الارتفاع الأساسي المعرّف في `StatusbarPart.HEIGHT` هو **22px**، وحجم الخط في CSS هو **12px**.
- عند استخدام تخطيط اللوحات العائمة يمكن أن يضاف فراغ سفلي إلى الجزء الرئيسي فقط: **6px** عادة أو **4px** في الكثافة الحديثة المدمجة. ارتفاع الجزء المساعد يبقى 22px.
- الحد الأقصى لعرض العنصر الواحد هو `40vw`، والنص لا يلتف، ويستخدم الاقتطاع عند تجاوز المساحة.
- تستخدم أرقام بعرض ثابت (`tabular-nums`) لتقليل اهتزاز عرض الحالات الرقمية، مثل العدادات.

التخطيط وإظهار الجزء أو إخفاؤه من مسؤوليات Workbench؛ إعداد `workbench.statusBar.visible` افتراضيه `true`. أمر **Toggle Status Bar Visibility** يبدل هذا الإعداد. لذلك إخفاء الشريط ككل مختلف عن إخفاء عنصر داخله.

## 4. نموذج العنصر ومواصفاته

يمثل `IStatusbarEntry` وصفاً declarative لعنصر واحد. أهم الحقول:

| الحقل | الغرض |
| --- | --- |
| `name` | اسم وصفي قصير؛ يستخدم في قوائم الإدارة والإخفاء. |
| `text` | المحتوى المرئي. يمكن تضمين أيقونات Codicon بصيغة `$(icon-name)`. |
| `ariaLabel` | النص المعلن لقارئ الشاشة. |
| `role` | دور العنصر؛ الافتراضي `button`. |
| `tooltip` | نص أو Markdown أو محتوى hover مدعوم، ويمكن أن يتضمن أوامر في ذيل التلميح. |
| `command` | أمر ينفذ عند النقر أو اللمس؛ يدعم أيضاً أمري عرض التلميح أو تبديله. |
| `showProgress` | إظهار أيقونة تقدم متحركة، مع نمطي `loading` و`syncing`. |
| `kind` | نمط دلالي/لوني للعنصر. الأنواع: `standard`, `warning`, `error`, `prominent`, `remote`, `offline`. |
| `color`, `backgroundColor` | ألوان مخصصة؛ موصوفة كحقول قديمة في العقد الداخلي لصالح `kind`. |
| `showBeak` | رسم مؤشر صغير أعلى العنصر، مثل مؤشر مرتبط بإشعار. |
| `showInAllWindows` | نشر العنصر في النوافذ المساعدة الحالية والجديدة. |
| `extensionId` | هوية الإضافة المساهمة؛ تتيح إجراءات إدارة الإضافة من قائمة السياق. |
| `content` | عنصر HTML مخصص؛ متاح للحالات الخاصة، مع تفضيل `text` متى أمكن. |

إضافة العنصر تتم عبر `addEntry(entry, id, alignment, priority)`، وتعيد accessor له `update(...)` و`dispose()`. هكذا يمكن للمساهمة تحديث المحتوى من دون إعادة إنشاء الجزء، ثم التخلص من العنصر عند انتهاء دورة حياتها.

ملاحظة: عقد `IStatusbarEntry` الداخلي أوسع من العقد العام للإضافات. بعض الحقول أو أنماط العرض الداخلية لا تكون بالضرورة متاحة في API العامة.

## 5. المحاذاة والترتيب والعناصر المترابطة

يخزن النموذج العناصر في مصفوفة عمداً، لا في خريطة، لأن أكثر من عنصر قد يحمل المعرّف نفسه (مثلاً عند تكرار مساهمة من إضافة).

### الأولوية الرقمية

- يقبل العنصر محاذاة `LEFT` أو `RIGHT`.
- الأولوية الأعلى يظهر ترتيبها أقرب إلى يسار مجموعته؛ في المجموعة اليسرى يعني ذلك أقرب إلى أقصى اليسار، وفي اليمنى يطبق DOM عكس الاتجاه باستخدام `row-reverse`.
- عند تساوي الأولوية الأساسية تستخدم أولوية ثانوية، ثم يحافظ النموذج على ترتيب الإدراج المستقر.
- إذا لم تقدم أولوية داخلية ثانوية، يشتقها التنفيذ من hash للمعرّف لتقليل تصادمات الترتيب.

### التموضع نسبة إلى عنصر آخر

يمكن تحديد أولوية نسبية عبر `IStatusbarEntryLocation`:

- `location.id`: معرّف العنصر المرجعي.
- `location.priority`: قيمة احتياطية إذا لم يكن المرجع موجوداً.
- `alignment`: وضع العنصر قبل المرجع أو بعده.
- `compact`: طلب تقارب بصري بين العنصرين.

يفصل `StatusbarViewModel.sort()` العناصر التي لها مرجع قائم عن العناصر ذات الأولوية الرقمية، ثم يركب العناصر النسبية حول المرجع. وإذا كان المرجع غائباً يستخدم قيمة الأولوية الاحتياطية. وعند الإزالة يعيد الترتيب إذا كانت عناصر أخرى تشير إلى العنصر المحذوف.

`compact` ليس مجرد ترتيب: يضيف `StatusbarPart` أصناف `compact-left` و`compact-right`، ويعدل الهوامش، ويربط تأثير hover لعناصر المجموعة المتقاربة. الهدف هو إظهار أجزاء مثل اسم مزود التحكم بالمصدر وأوامره كأنها مجموعة واحدة.

## 6. كيف يُبنى العنصر ويُحدّث

عند إنشاء كل عنصر:

1. ينشئ `StatusbarPart` حاوية `.statusbar-item` ويصنفها `left` أو `right`.
2. ينشئ `StatusbarEntryItem` وداخله عنصر تسمية `a.statusbar-item-label` مع `tabIndex=-1`؛ ثم يضيف حاوية مؤشر الـ beak عند الحاجة.
3. يضيف العنصر إلى `StatusbarViewModel`، الذي يطبق حالة الإخفاء ويرتب القائمة.
4. يدرج DOM في حاوية المحاذاة المناسبة. العناصر اليمنى تعكس ترتيب إدراجها بسبب اتجاه Flex.
5. يحدث الأصناف الخاصة بالعناصر المدمجة والجيران ذوي الخلفيات.

إذا أضيف عنصر قبل إنشاء مساحة DOM، يحتفظ به الجزء كعنصر pending. عندما ينشئ `createContentArea` الحاويتين، يدرج العناصر السابقة ثم يفرغ قائمة pending. هذا يسمح للخدمات بالمساهمة قبل اكتمال إنشاء واجهة Workbench.

التحديث يمر عبر accessor إلى `StatusbarEntryItem.update()`، الذي يغير فقط الأجزاء التي تغيرت: نص الأيقونة، تسمية الوصول، hover، command listeners، اللون، الخلفية، النوع، وإشارة التقدم. أما إزالة العنصر فتزيله من النموذج وDOM وتتخلص من مستمعاته وموارده.

النص الذي يحوي أيقونات يمر عبر renderer الخاص بعناوين الأيقونات. وعند تفعيل التقدم يعرض عنصر التسمية أيقونة التحميل أو المزامنة أولاً، مع إعادة استخدام عقدة الأيقونة كي لا تعاد الحركة من البداية عند كل تحديث نص.

## 7. التفاعل وقابلية الوصول

- النقر، اللمس، و`Enter` أو `Space` تشغل الأمر المرتبط بالعنصر.
- ينفذ الأمر عبر `ICommandService`؛ عند الفشل يعرض التنفيذ رسالة خطأ عبر خدمة الإشعارات. ويُسجل تنفيذ الأمر لأغراض telemetry.
- أمري `ShowTooltipCommand` و`ToggleTooltipCommand` يفتحان الـ hover أو يثبتانه/يخفيانه، ولا يمرران الأمر إلى command service.
- الـ hover قد يكون نصاً أو Markdown، وقد يحتوي أوامر في تذييل التلميح، ويمكن تشغيل callback عند ظهوره.
- تتعامل الأحداث مع الماوس واللمس؛ كما يسمح الزر الأيمن/قائمة السياق بإدارة الشريط والعناصر.
- العنصر يضع `aria-label` على الحاوية وعلى التسمية لتجنب فقدان الوصف عند اختلاف موضع التركيز. يمكن تحديد `role` يدوياً.
- التسمية لا تدخل ترتيب Tab العادي (`tabIndex=-1`)؛ عند تركيز الشريط تستخدم أوامر التنقل: الأسهم التالية/السابقة، `Home` و`End` للأول/الأخير، و`Escape` لإزالة التركيز أو الرجوع إلى المحرر النشط. يوجد أيضاً أمر **Focus Status Bar**.
- عند إخفاء العنصر تزال رؤيته بواسطة CSS مع تحديث علامات أول/آخر عنصر مرئي، ويُتخطى العنصر المخفي عند التنقل بالتركيز.

## 8. الإخفاء وإدارة العناصر

قائمة السياق على الشريط توفر:

1. أمراً لإخفاء شريط الحالة بأكمله.
2. قائمة بالعناصر المعروفة، مع إمكانية تشغيل/إيقاف ظهورها.
3. عند فتح القائمة فوق عنصر، إجراء لإخفاء ذلك العنصر، وإجراء لإدارة الإضافة المالكة إذا كان العنصر تابعاً لإضافة.

تُخزن معرّفات العناصر المخفية في ملف تعريف المستخدم تحت المفتاح:

`workbench.statusbar.hidden`

يحمل `StatusbarViewModel` هذه الحالة عند الإنشاء، ويحفظها عند الإخفاء/الإظهار، ويراقب تغييرات التخزين حتى تبقى الحالة متزامنة. المعرّف هو مفتاح الإخفاء، لذا فإن العناصر التي تشترك في المعرّف تتأثر معاً.

## 9. الألوان والسمات والتخطيط المرئي

يستمد الجزء ألوانه من ألوان Theme registry، ويحدثها عند تغير السمة. يختلف لون الخلفية والواجهة عند عدم وجود مجلد/مساحة عمل، وعند فقدان تركيز النافذة. كما يمكن للمساهمات المؤقتة استخدام `overrideStyle`; وعند وجود عدة overrides تطبق القيمة ذات الأولوية العددية الأقل.

تتضمن أنماط CSS:

- خلفية ونص الشريط وحده العلوي وفق ألوان الثيم.
- مؤشرات hover وactive وتحديد التركيز، مع مراعاة ألوان التباين العالي.
- أصناف `warning-kind`, `error-kind`, `prominent-kind`, `remote-kind`, `offline-kind` تربط حالات العنصر بألوان ثيم مثل `statusBarItem.warningBackground` و`statusBarItem.errorBackground`.
- ضبط حواف العنصر الأول والأخير والخلفيات الملونة كي تتصل بصرياً بحافة الشريط.
- فروق هوامش وحشوات للعناصر المتقاربة `compact`.
- مؤشر beak يطابق لونه الحد/الخلفية.
- انتقال خلفية قصير عند تفعيل الحركة.

الألوان المخصصة من نوع `ThemeColor` يعاد حلها عند تغير الثيم، وتزال مستمعات الألوان السابقة عند التحديث أو التخلص منعاً لتراكمها.

## 10. أمثلة لمساهمات النظام

الخدمات والمساهمات الداخلية تستخدم الخدمة المشتركة نفسها، ولا تتطلب أن تكون جزءاً من شيفرة `StatusbarPart`. أمثلة مؤكدة من الشيفرة:

| المساهمة | مثال على السلوك |
| --- | --- |
| Source Control | يضيف أوامر المستودع النشط على اليسار؛ قد يربط اسم المزود بالعناصر القريبة بـ `compact`. |
| Problems/Markers | يضيف عنصر عدد المشكلات، ويحدثه عند تغير العلامات؛ وقد يضيف عنصر حالة بديل عند تعطيل عرض المشكلات. |
| Debug | عنصر حالة تصحيح أخطاء ذي أولوية محددة. |
| Remote | مؤشر المضيف البعيد بأولوية مرتفعة كي يظهر مبكراً. |
| المهام واللغة | تضيف عناصر حسب حالة المشروع/المحرر، ويمكن وضعها نسبة إلى عناصر أخرى. |

هذا يوضح أن الشريط إطار عرض عام لحالات السياق، وليس مصدراً للحالة نفسها؛ كل مساهمة تملك منطقها وتحدث entry عند تغير بياناتها.

## 11. مسار API الإضافات

### العناصر الديناميكية (`window.createStatusBarItem`)

واجهة `vscode.window.createStatusBarItem(...)` تنشئ العنصر في Extension Host. يمكن تحديد المعرّف والمحاذاة والأولوية عند الإنشاء. يضبط المطور الخصائص (`text`, `name`, `tooltip`, `color`, `backgroundColor`, `command`, `accessibilityInformation`)، ثم يستدعي `show()` و`hide()` و`dispose()`.

مسار البيانات مفاهيمياً:

```text
Extension API / ExtHostStatusBarEntry
    └── تحديث مجمّع مؤجل إلى دورة الحدث التالية
        └── RPC ($setEntry / $disposeEntry)
            └── Main Thread + ExtensionStatusBarItemService
                └── IStatusbarService.addEntry أو accessor.update
                    └── StatusbarPart / StatusbarEntryItem
```

يجمع Extension Host عدة تحديثات متتابعة قبل الإرسال عبر مؤقت صفري لتجنب إعادة رسم متكررة. الإخفاء يرسل التخلص من entry على الخيط الرئيسي، ويمكن لـ `show()` نشره مجدداً. يحتفظ التنفيذ بمعرّف داخلي فريد، ويضيف معرّف الإضافة إلى المعرّفات المسماة لتمييز العناصر بين الإضافات. في عنصر موجود سلفاً من مساهمة ثابتة، قد يستعيد الإنشاء خصائص العنصر الثابت.

المحاذاة والأولوية تحددان عند إنشاء العنصر؛ يثبتها `ExtensionStatusBarItemService` للتحديثات اللاحقة. كما تقيد الواجهة العامة لون الخلفية بالألوان المعتمدة للتحذير والخطأ، ويمكنها ضبط لون النص الملائم تلقائياً.

### المساهمة الثابتة في `package.json`

يعرف `statusBarExtensionPoint.ts` نقطة مساهمة `statusBarItems` بمخطط يحوي `id`, `name`, `text`, `alignment`، وحقولاً اختيارية مثل `tooltip`, `command`, `priority`, `accessibilityInformation`. في نسخة المصدر محل التحليل هذه، نقطة المساهمة معرفة كـ **Proposed API** وتُرفض ما لم تكن واجهة المقترح مفعلة للإضافة. يجب عدم الخلط بينها وبين واجهة `window.createStatusBarItem` المنشورة في `vscode.d.ts`.

## 12. تعدد النوافذ والنطاقات

- `StatusbarService` هو خدمة متعددة النوافذ، ويبدأ بـ `MainStatusbarPart`.
- تنشأ `AuxiliaryStatusbarPart` داخل نافذة/حاوية مساعدة، ولها نموذجها وعناصرها.
- entry الذي يحمل `showInAllWindows` يضاف لكل الأجزاء الحالية، ويضاف تلقائياً إلى كل جزء مساعد ينشأ لاحقاً؛ accessor موحد يحدّث النسخ ويزيلها.
- `createScoped(...)` ينشئ خدمة محصورة على `IStatusbarEntryContainer` معين، مع تمرير بعض عمليات الإنشاء/التفويض إلى الخدمة الأصلية.
- تظهر تغيرات الثيم والتركيز في الألوان؛ لكل نافذة status bar مناسب لهويتها/تركيزها.

## 13. دورة الحياة والأحداث والحدود المعمارية

أهم مسارات العمل:

**الإضافة:** `addEntry` ← تجهيز أولوية ← pending إن لم يوجد DOM، وإلا إنشاء عنصر DOM/model ← فرز ← إدراج وتحديث التنسيقات.

**التحديث:** accessor `update` ← تطبيق أي override ← تحديث الحقول المتغيرة ← إعادة فحص الخلفية المجاورة إذا تغيرت حالة الخلفية.

**الإزالة:** accessor `dispose` ← إزالة العنصر من النموذج ← إعادة بناء الترتيب عند الحاجة ← إزالة DOM والمستمعات.

**الظهور:** تغيير الحالة في النموذج ← تطبيق الإخفاء والإظهار ← إطلاق `onDidChangeEntryVisibility` ← تحديث المجموعات والعناصر المرئية.

`StatusbarPart` مرتبط بخدمات Workbench (السمة، التخزين، السياق، التخطيط، التركيز، القوائم والـ hover). لذلك إنشاء نسخة مستقلة للشريط لا يساوي استنساخ عنصر UI فقط؛ يلزم توفير هذه الخدمات أو عزل العقد اللازم منها.

## 16. الاستنتاج التصميمي

أهم ما يميز تصميم VS Code هو فصل **حالة الميزة** عن **آلية العرض**: الميزة تملك بياناتها وتحديثاتها، والخدمة تقدم نقطة مساهمة موحدة، والنموذج يتولى الترتيب والإخفاء، وعنصر العرض يتولى التفاعل وإمكانية الوصول، وCSS/Theme يتوليان المظهر. يسمح ذلك بتوسيع الشريط من دون جعل الجزء الأساسي يعتمد على كل ميزة على حدة.

عند تبني هذا النهج في محرر آخر، ينبغي الحفاظ على عقد واضح للعنصر، accessor للتحديث والتخلص، أولوية مستقرة، إدارة تفضيلات الإخفاء، وإمكانية وصول كاملة؛ ثم إبقاء قواعد العرض والتخطيط منفصلة عن مصادر البيانات. أما دعم النوافذ المساعدة وHTML المخصص والألوان الديناميكية فيضاف فقط إذا كان المنتج يحتاجها، لأنها ترفع تعقيد دورة الحياة والخدمات.
