# الخطة التنفيذية لبناء محرر الأكواد (Code Editor Implementation Plan)

تستند هذه الخطة إلى التحليل المعماري لواجهة **VS Code Workbench** وتحدد المراحل العملية خطوة بخطوة لبناء محرر أكواد متقدم وقابل للتوسع لأي لغة برمجية باستخدام إطار عمل **Flutter** كواجهة مكتبية (Desktop-First: Linux / macOS / Windows).

---

## 🧭 الرؤية والأهداف المعمارية

1. **أداء سلس (60/120 FPS):** فصل عمليات سحب الحواف وإعادة تحجيم النوافذ (Resize) عن رندر النصوص لتجنب أي Lag.
2. **استقلالية اللغات (Language-Agnostic):** معمارية فصل تامة بين هيكل الواجهة (Shell) ومحرك معالجة اللغات (Syntax Highlighting / LSP).
3. **تصميم عصري وقابل للتخصيص (Modern & Extensible UI):** دعم الثيمات الداكنة/الفاتحة، الفواصل التفاعلية، والنوافذ القابلة للإخفاء والتوسيع.

## 🛠️ التفصيل التنفيذي لكل مرحلة

### المرحلة 1: التأسيس ونظام التصميم (Foundation & Design System)

*الهدف: إنشاء اللبنات الأساسية للمظهر والمقاييس لضمان تصميم موحد واحترافي.*

- **1.1. شجرة المجلدات الهندسية:**
  - بناء هيكلية الحزم داخل `lib/` وفق التقسيم المعماري (`core`, `layout`, `parts`, `services`, `models`).
- **1.2. نظام الألوان والسمات (Theme System):**
  - بناء لوحة ألوان مستوحاة من البيئات الاحترافية الحديثة (Dark Slate / Deep Gray).
  - تحديد ألوان العناصر الرئيسية: خلفية المحرر، خلفية الشريط الجانبي، حدود الفواصل، ولون التبويب النشط.
- **1.3. الخطوط والأيقونات (Typography & Icons):**
  - اعتماد خط برمجي عالي الدقة للنصوص (مثل `JetBrains Mono` أو `Fira Code`).
  - اعتماد خط واجهة عصري (مثل `Inter` أو `Plus Jakarta Sans`).
  - إعداد حزمة أيقونات متكاملة لملفات اللغات وأيقونات الأنشطة.

---

### المرحلة 2: هيكل التخطيط الشبكي والفواصل المرنة (Workbench & Grid Layout)

*الهدف: بناء الهيكل الهيكلي للنافذة الرئيسية مع فواصل قابلة للسحب لتغيير الحجم.*

- **2.1. ودجت الفاصل التفاعلي (`ResizableSplitter / Sash`):**
  - تصميم ويدجت يقبل اتجاه التقسيم (أفقي / رأسي) ويوفر استجابة لمؤشر الفأرة (`SystemMouseCursors.resizeColumn / resizeRow`).
  - دعم السحب السلس عبر `GestureDetector` مع حدود الحجم الأدنى والأقصى (`minWidth`, `maxWidth`).
  - دعم ميزة السحب لنقطة الصفر للإخفاء التلقائي (Snap to hide).
- **2.2. الحاوية الشاملة (`WorkbenchLayout`):**
  - بناء التقسيم الرأسي الشامل:
    - الصف 1: شريط العنوان العلوي (`TitleBar`).
    - الصف 2: القسم الأوسط القابل للتوسع (`Middle Section`).
    - الصف 3: شريط الحالة السفلي (`StatusBar`).
  - داخل القسم الأوسط: تقسيم أفقي يضم:
    - `ActivityBar` (ثابت 48px).
    - `Primary SideBar` (مرن بين 180px و 500px).
    - فاصل سحب أيسر (`Left Sash`).
    - مساحة المحرر المركزية (`Editor Area`) مدمج معها اللوحة السفلية (`Bottom Panel`) بفاصل سحب أفقي.
    - فاصل سحب أيمن (`Right Sash`).
    - `AuxiliaryBar` (الشريط الجانبي الأيمن).

---

### المرحلة 3: إدارة الحالة والحفظ التلقائي (Layout State & Persistence)

*الهدف: الاحتفاظ بحالة واجهة المطور حتى عند إعادة تشغيل التطبيق.*

- **3.1. نموذج بيانات التخطيط (`WorkbenchLayoutState`):**
  - أبعاد الأجزاء: `sideBarWidth`, `auxiliaryBarWidth`, `panelHeight`.
  - حالات الظهور: `isSideBarVisible`, `isPanelVisible`, `isAuxiliaryBarVisible`, `isActivityBarVisible`.
  - الأوضاع الخاصة: وضع التركيز (`ZenMode`) والتكبير الكامل للوحة أو المحرر.
- **3.2. تحسين الأداء (State Performance):**
  - استخدام `ChangeNotifier` أو `ValueNotifier` متخصصة ومستقلة لكل منطقة لمنع إعادة بناء شجرة الـ Widgets بالكامل أثناء السحب بالماوس.
- **3.3. التخزين المحلي (Local Storage):**
  - حفظ الإعدادات وقيم الأبعاد تلقائياً لاسترجاعها الفوري عند فتح المحرر.

---

### المرحلة 4: منطقة التحرير والتبويبات (Editor Part & Tabs System)

*الهدف: إنشاء نظام إدارة التبويبات المتعددة وسطح عرض الملف.*

- **4.1. شريط التبويبات (`EditorTabsControl`):**
  - عرض قائمة التبويبات المفتوحة مع أيقونة نوع الملف، اسمه، وزر الإغلاق (`x`).
  - مؤشر التعديل غير المحفوظ (`isDirty` / نقطة دائرية).
  - إمكانية التمرير الأفقي بالماوس إذا زاد عدد التبويبات.
  - دعم التبديل التفاعلي بين التبويبات بالنقر عليها.
- **4.2. مسار التتبع (`Breadcrumbs`):**
  - شريط مسار أسفل التبويبات يعرض اسم المجلد والملف والموقع داخل الكود.
- **4.3. سطح التحرير (`EditorSurface`):**
  - تقسيم مساحة التحرير إلى:
    - شريط الأرقام الجانبي (`Gutter`): ترقيم السطور، مؤشرات نقاط التوقف.
    - مساحة الكود النصية المجهزة للتمرير الرأسي والأفقي مع التزامن التام مع أرقام السطور.
    - الخريطة المصغرة (`Minimap`) الاختيارية على يمين المحرر.

---

### المرحلة 5: مستكشف الملفات والقوائم الجانبية (Primary SideBar & Views)

*الهدف: تصفح ملفات المشاريع وفتحها بسلاسة.*

- **5.1. نموذج شجرة الملفات (`FileTreeModel`):**
  - قراءة محتويات المجلدات المفتوحة عبر نظام الملفات المحلي (`dart:io`).
  - التمييز بين المجلدات والملفات وتحديد الامتدادات.
- **5.2. ويدجت مستكشف الملفات (`FileExplorerView`):**
  - شجرة قابلة للطي والتوسيع (Expand/Collapse Tree).
  - تفاعل النقر الفردي (Preview Tab) والنقر المزدوج (Keep Tab Open).
  - دعم القوائم المنبثقة (Right Click Menu: New File, New Folder, Rename, Delete).

---

### المرحلة 6: شريط الأنشطة وشريط الحالة (ActivityBar & StatusBar)

*الهدف: توفير سهولة التنقل ومراقبة حالة المشروع والملف النشط.*

- **6.1. شريط الأنشطة (`ActivityBar`):**
  - أيقونات التنقل الأساسية: المستكشف، البحث، فحص الأخطاء، الإعدادات.
  - مؤشر مرئي للتبويب النشط (Active indicator line).
  - النقر على الأيقونة النشطة يغلق/يفتح الشريط الجانبي تلقائياً (كما في VS Code).
- **6.2. شريط الحالة (`StatusBar`):**
  - الطرف الأيسر: اسم الفرع الحالي (Git)، مؤشرات الأخطاء والتحذيرات.
  - الطرف الأيمن: موقع المؤشر (`Ln 12, Col 34`)، حجم المسافات البادئة (`Spaces: 2`)، ترميز الملف (`UTF-8`)، واللغة المكتشفة.

---

### المرحلة 7: اللوحة السفلية والشريط الإضافي (Panel & AuxiliaryBar)

*الهدف: دمج بيئة التشغيل والمساعد الذكي.*

- **7.1. اللوحة السفلية (`Panel`):**
  - نظام تبويبات سفلي:
    - **Problems:** جدول الأخطاء والتحذيرات مع رقم السطر وإمكانية القفز إليه.
    - **Output:** سجلات وسجلات تشغيل المخرجات.
    - **Terminal:** حاوية مجهزة لدمج طرفية الأوامر.
  - أزرار التحكم باللوحة: تصغير، تكبير لكامل الشاشة (Maximize)، وإغلاق.
- **7.2. الشريط الجانبي الإضافي (`AuxiliaryBar`):**
  - مساحة مخصصة للمساعد الذكي ومخطط كود الدوال (`Outline / Code Symbols`).

---

### المرحلة 8: مركز الأوامر والاختصارات (Command Center & Shortcuts)

*الهدف: رفع كفاءة التفاعل والتحكم بالمحرر عبر لوحة المفاتيح.*

- **8.1. مركز الأوامر والبحث (`Command Center` في شريط العنوان):**
  - شريط بحث وسطي ينبثق كـ (`Command Palette` / نافذة منبثقة عائمة).
  - دعم الاختصار العالمي `Ctrl+Shift+P` لتنفيذ كل عمليات المحرر بسرعة.
  - دعم اختصار `Ctrl+P` للبحث الفوري في أسماء الملفات والانتقال إليها.
- **8.2. مدير الاختصارات العالمية (`KeybindingService`):**
  - دعم اختصارات الحفظ (`Ctrl+S`)، إغلاق التبويب (`Ctrl+W`)، وتقسيم المحرر.

---

### المرحلة 9: محرك اللغات والتظليل اللوني وتكامل LSP (Language Engine)

*الهدف: دعم أي لغة برمجية بدون كتابة منطق مخصص لكل لغة على حدة.*

- **9.1. هيكل المحلل النحوي القابل للتمديد:**
  - استخدام محلل قواعد عام (مثل قواعد `TextMate Grammars` أو `Tree-sitter bindings`).
  - خريطة سمات الألوان (Syntax Token Scope Mapping) لربط الرموز بقواعد الثيم.
- **9.2. تكامل بروتوكول خادم اللغة (`Language Server Protocol - LSP`):**
  - بنية تحتية لربط المحرر بأي خادم LSP خارجي لأي لغة (Dart Analysis Server, Pyright, gopls, rust-analyzer).
  - توفير ميزات: الإكمال التلقائي (Autocomplete)، التنقل للتعريف (Go to Definition)، وفحص الأخطاء التلقائي (Diagnostics).
